# Telegram Jarvis (Rust)

A Telegram assistant bot in Rust. Ingests DM/group messages into SQLite,
retrieves relevant history (lexical RAG), and answers via the **Claude Code CLI**
running as a long-lived streaming subprocess. MCP tools cover the Telegram Bot
API, persistent memory, reminders, cron tasks, FACEIT CS2 stats, Google Sheets,
Gmail/SMTP, and web fetch/search.

- DM + group message ingestion, SQLite persistence
- Lexical RAG over stored history (no embeddings)
- Answers generated by Claude Code (`claude --print` stream-json subprocess)
- Triggered group replies (mention, reply-to-bot, alias) + proactive cold trigger
- Image vision (base64 to Claude); voice messages stored as metadata
- Uzbek-first: understands any language, replies in Uzbek
- Webhook mode (with long-poll fallback)
- File-based prompts in `prompts/`

> Backend is Claude Code. There is no Codex CLI and no MTProto/user-account mode;
> the `CODEX_*` env vars and the crate name are legacy aliases.

## Requirements

- Rust stable toolchain
- Claude Code CLI (`claude`), authenticated — see auth notes below
- Node.js (only to install/run the `claude` CLI)
- Telegram bot token from BotFather
- Public HTTPS URL only for webhook mode

System build deps (Ubuntu): `build-essential pkg-config libssl-dev`.

## Configure

Copy `.env.example` → `.env` and set:

- `TELOXIDE_TOKEN` — bot token from BotFather
- `CLAUDE_CODE_BIN` (default `claude`), `CLAUDE_CODE_MODEL`, `CLAUDE_CODE_TIMEOUT_SECS`
- `ANTHROPIC_API_KEY` — for headless claude auth (or use `claude setup-token`, below)
- `OWNER_USER_ID` — **required**; the bot replies only to this Telegram user id (falls back to the first `ALLOWED_USERS` entry)
- `BOT_ALIASES` — group trigger words (e.g. `jarvis,bot`)
- `DATABASE_URL` (default `sqlite://data/jarvis.db`)
- `SYSTEM_PROMPT_FILE` / `USER_RULES_FILE`
- `WEBHOOK_URL` (set for webhook mode; empty = long polling) / `WEBHOOK_BIND`

See `.env.example` for the full list (proactive triggers, FACEIT API, Sheets,
Gmail/SMTP).

### Claude Code auth (headless server)

Pick one:
- **API billing**: set `ANTHROPIC_API_KEY` in `.env`. The subprocess inherits it.
- **Subscription billing**: run `claude setup-token` (or `claude login`) as the
  service user so `~/.claude/.credentials.json` exists.

## Telegram group reads

In BotFather, disable privacy mode so the bot sees normal group messages:
`/mybots` → your bot → `Bot Settings` → `Group Privacy` → `Turn off`. Then add the
bot to the group.

## Run (dev)

```bash
cargo run                     # bot
cargo build --release         # release binaries: telegram-codex-jarvis, mcp-telegram
```

Behavior:
- Every DM/group message is stored.
- Private chat: responds only to `ALLOWED_USERS`.
- Groups: responds on `@mention`, reply-to-bot, or a `BOT_ALIASES` word; plus an
  optional LLM "cold trigger" and active-follow-up window (see `CLAUDE.md`).
- Privacy guardrails: system/architecture/internal config questions are refused.

## Webhook mode

```
WEBHOOK_URL=https://your-domain.com/telegram/webhook   # public HTTPS (443/80/88/8443)
WEBHOOK_BIND=0.0.0.0:8081                               # internal upstream
```

Empty `WEBHOOK_URL` → long polling.

## Deploy (Ubuntu server)

One-shot bootstrap + full runbook: **`deploy/README.md`**.

```bash
JARVIS_USER=<service-user> bash deploy/setup-ubuntu.sh
sudo systemctl start jarvis-bot
journalctl -u jarvis-bot -f
```

## Data storage

SQLite at `DATABASE_URL` (default `sqlite://data/jarvis.db`). Schema documented in
`CLAUDE.md` (core tables: chats, users, messages, focus, memory, reminders,
scheduled tasks, security, monitored groups, heartbeats, chat profiles).
